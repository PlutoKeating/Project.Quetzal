# 终端对话

运行基座已经安装、启动并配置模型后，在交互终端执行：

```bash
quetzal tui
quetzal chat --conv <已有会话ID>
quetzal tui --home <运行基座家目录>
```

chat 与 tui 是同义入口。这是第一阶段的行式终端界面，支持边输入边接收进展；没有独立人格或模型配置，App、飞书、终端共用运行基座与已有会话。默认打开最近会话，没有会话则创建「终端对话」。只连接配置端口的 `127.0.0.1` 网关，不接受远程地址或命令行令牌。

| 输入 | 行为 |
|---|---|
| 普通文字 | 发往当前会话，默认 steer 插话；不会等回复完成才允许下一次操作 |
| /sessions | 列出已有会话与编号 |
| /use 编号 | 切换会话并显示最近历史 |
| /new [标题] | 新建会话 |
| /history | 最近 10 条非环境消息 |
| /approvals | 刷新待审批动作，展示动作和原因；不显示完整工具参数 |
| /approve 编号、/deny 编号 | 对该次列表里的 body/id 决定批准或拒绝；不修改长期授权设置 |
| /stop、Ctrl-C | 请求停止当前会话的一轮；退出不自动停止后台任务 |
| /reconnect | 断线后手动重连并恢复状态；不重发之前的消息或操作 |
| /help | 显示命令 |
| /quit、/exit、Ctrl-D | 关闭终端客户端；运行基座继续运行 |

模型文字流和工具名称/状态会显示，完整工具参数、摘要与输出不在终端展示，需要审查完整动作时用 `quetzal open`。所有远端文字过滤 ANSI/OSC 等终端控制序列与双向排版标记；不维护 readline 输入历史。

## 认证与保密输入

使用运行基座同一用户和正确家目录，客户端优先读取 `secrets/gateway.token`；读不到才请求回环 `/auth/local`，由运行基座检查同用户及进程关系。Windows 的回环原生登录依赖本机令牌文件。令牌不打印、不进 URL，不增加令牌配置或配对旁路。连接失败不会自动启动、安装或修改运行基座。

终端不接收保密值。启动/重连先查询 `secrets.pending`，每次普通发送前再次核对，收到当前会话的 secret open/progress 时立即屏蔽 readline 回显并清空尚未提交的输入。普通输入不发送；请用控制台完成或取消保密传递。此时无正文 slash 管理命令与数字会话/审批编号仍可使用但不回显；带正文的 `/new 标题` 等输入拒绝发送。恢复快照期间的 secret 增量在快照后回放，普通输入在发送前还会复核会话与保密/连接状态。readline 收到每行时固定当时的保护状态：保密/断线期间的正文立即拒绝，不进入等待其他命令完成的输入队列；之后恢复连接或结束保密输入，也不会补发这些内容。不要在普通终端对话里主动输入凭据：保密模式开始之前的普通行仍是普通聊天，不是安全输入框。

## 断线与当前限制

断线时屏蔽输入回显，已发送操作的结果可能未知；客户端不会重试 chat.send、审批或其他修改。/reconnect 重新读取令牌，恢复 sessions/live/approvals/secrets.pending，并显示最近历史。用 /history 或控制台确认先前动作，不要把断线当作动作未执行。RPC 无进展 45 秒提示结果未知；网关每 10 秒 rpc.progress 会刷新计时，因此长任务有进展时不受绝对 45 秒限制。

第一阶段没有附件/语音输入、全屏布局、终端配对、远程 TLS 连接或保密值采集。跨身体会话与审批通过已有网关路由。退出客户端不会停止自主思考或其他会话；要停止当前会话先 /stop。

验证命令：`npm test`、`npx tsc --noEmit`（在 cli 下）。新增测试使用 Node 内置 HTTP/crypto 的合成 WebSocket 网关，不调用真实模型、不读取部署者家目录、不依赖 runtime。既有打包入口自动收录 tui.ts，发布文件布局与运行依赖不变。
