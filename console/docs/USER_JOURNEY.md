# 用户旅程：安装 → 登录 → 使用

目标只有一句话：**从打开 App 到和 ta 说上第一句话，用户只做三件事——装、登录、选模型。** 其余一切要么自动完成，要么藏起来不打扰。

判断每一个步骤、每一句文案的标准：

1. **用户需要操心吗？** 能自动的一律自动，能默认的一律默认。
2. **用户看得懂吗？** 看不懂的东西（时间常数、SSH 模式、协调者优先级）不该让用户做，交给 ta 自己调或收进「高级」。
3. **一眼能明白就不写说明。** 产品里不贴说明书；说明一律放文档。一页最多一句必要的话。

## 1. 现在的完整链路

图例：✅ 自动完成，用户看不到；🔵 用户必须做的一步；⚪ 可跳过；🗂 收进「高级」。

### 1.1 新用户 · 安卓手机

| # | 步骤 | 现在 | 说明 |
|---|---|---|---|
| 1 | 下载安装 APK | 🔵 | 唯一绕不开的系统操作 |
| 2 | 打开 App，发现本机没有运行基座 | ✅ | 直接进安装向导，不再先显示「连接一个 agent」让人选 |
| 3 | 解开运行环境、启动、连上 | ✅ | 打开向导就开始，没有「安装」按钮；令牌从家目录读，不需要配对码 |
| 4 | 相机、麦克风、位置、通知权限 | 🔵 | 装好立即自动弹出系统权限请求；用之前仍按授权询问 |
| 5 | 后台运行（忽略电池优化） | 🔵 ⚪ | 一个「允许」；能检测到已允许就自动打勾；厂商自启动页是次要入口 |
| 6 | 登录 | 🔵 ⚪ | 「用 GitHub 登录」→ 申请到码**直接打开浏览器**→ 网页上批准；新账户自动建 agent、自动建并接好私有灵魂仓库；同一次批准也让这台设备能管理账户（一次登录） |
| 7 | 选择模型 | 🔵 | 点一个供应商、粘贴一个 Key、「接上」；挑模型、试通、排序全自动。唯一需要用户带着信息来的一步 |
| 8 | 开始对话 | — | 首页没有模型时只有一个入口「选择模型」，有了就消失 |

### 1.2 老用户 · 新设备

与新用户相同，差别全在第 6 步之后自动发生：批准时选中已有的 agent（只有一个时默认选中）→ 灵魂仓库自动接上、拉下人格与记忆 → 与在线的其他设备直连后，模型、Key、语音密钥与设置自动同步过来 → 第 7 步自动打勾，直接开始。

### 1.3 Linux 电脑

| # | 步骤 | 现在 |
|---|---|---|
| 1 | 一行安装命令 | 🔵 |
| 2 | 托盘、开机自启、桌面图标 | ✅ |
| 3 | 打开控制台，连本机运行基座 | ✅ 免配对码（桌面版读家目录里的网关令牌，网页版问 `/auth/local`） |
| 4 | 第一次连上、还没有模型：向导自动打开一次 | ✅ |
| 5 | 登录 | 🔵 ⚪ 同安卓 |
| 6 | 选择模型 | 🔵 同安卓 |

### 1.4 Windows 电脑

| # | 步骤 | 现在 |
|---|---|---|
| 1 | 下载页的安装程序，或一行 PowerShell 命令 | 🔵 |
| 2 | 一次 UAC（沙箱用户、开机任务、缺的 Node / Git / Python） | 🔵 |
| 3 | 开机自启运行基座、登录时托盘与身体助手、开始菜单图标 | ✅ |
| 4 | 打开控制台，连本机运行基座 | ✅ 免配对码（读家目录里的网关令牌） |
| 5 | 第一次连上、还没有模型：向导自动打开一次 | ✅ |
| 6 | 登录 | 🔵 ⚪ 同安卓 |
| 7 | 选择模型 | 🔵 同安卓 |

关窗只是收进托盘；升级后新版本由托盘悄悄换上（窗口开着时一条「新版本已装好 · 重新打开」）。电脑上的耳朵与 Linux 一样在控制台里，她说话时不收音、不能插嘴。

### 1.5 日常使用中的「看不见」

| 场景 | 现在 |
|---|---|
| App 有新版本 | 一条横幅「新版本 x」→ 更新 |
| App 更新后运行基座落后 | ✅ 后台自动重启成新版本，横幅只显示「正在更新…」；失败才给「重试」 |
| 断线 | ✅ 自动退避重连；本机运行基座停了才给「启动」 |
| 记忆同步、设备之间的设置同步 | ✅ 全自动，只在出错时出现在「高级 · 同步」 |
| 性格节律、语速音调、听觉的会话窗口与识别语言 | ✅ ta 自己调（`adjust_self` / `voice_config` / `hearing_config`）；你只要对 ta 说 |
| Azure 语音的区域 | ✅ 只填密钥，区域自动找出 |
| 在 App 里管理账户 | ✅ 设备登录那一次批准就够了，不再单独登录 |

## 2. 「控制」的信息架构

自上而下：先问每一页**谁会来、多久来一次**，再决定它住在哪。

```
控制
├── ● 神谷薰  简介                → 身份（名字、代词、简介、语言、颜色）
├── 模型          未设置时标红        必须：没有它 ta 不能思考
├── 权限          n 个待批准          待批准 + 每类能力 允许/询问/禁止（原「审批」+「能力授权」）
├── 节律          已暂停              活跃度（安静 ↔ 活跃）+ 暂停（原「自主性」，去掉性格参数）
├── 声音          在听                ta 的声音 + 听你说话（原「语音」+「听觉」）
├── 飞书
├── 设备          n 台在线            登录、设备列表、账户入口（原「多具身体」）
│   └── 账户                          概览 · 添加设备 · 已登录 · 设置
├── 高级
│   ├── 工具 · 保密库 · 预算
│   ├── 同步      灵魂仓库、同步服务地址、心跳优先级、接入 Hermes / OpenClaw（原「灵魂同步」+ 多具身体里的进阶项）
│   ├── 记忆历史 · 操作记录（原「审计日志」）
│   └── 运行      状态、沙箱、守护、重启 / 重装 / 重新配对（原「服务」）
└── 关于
```

| 原来 18 项 | 去向 | 理由 |
|---|---|---|
| 身份 | 顶部名字行 | 它是「ta 是谁」，不是一项设置 |
| 自主性 | 节律 | 只留一根滑杆和一个开关；性格参数交给 ta |
| 审批 + 能力授权 | 权限 | 同一件事的两面：ta 要做什么、ta 能做什么 |
| 语音 + 听觉 | 声音 | 同一把 Azure 密钥，嘴和耳朵放一起 |
| 多具身体 + 账户 | 设备 › 账户 | 用户心里只有「我的设备」 |
| 灵魂同步 | 高级 · 同步 | 登录时已自动接好，只有自己部署才来 |
| 工具、保密库、预算、记忆历史、审计日志、服务 | 高级 | 偶尔才看，不占首屏 |
| 关于 | 关于 | 必要，保持一步可达 |

首屏从 18 项、5 个分组标题，变成 6 项 + 高级 + 关于，没有分组标题；每项右侧最多一个短状态（「未设置」「1 个待批准」「在听」「2 台在线」），没有副标题说明。

## 3. 文案原则（与改动示例）

| 原文 | 现在 | 原则 |
|---|---|---|
| 醒来率的整体倍率。不是定时：只是让她整体更容易或更不容易醒来。 | 活跃度：安静 ↔ 活跃 | 用两端的词代替解释 |
| 她保持在线，会回应你，但不会自己醒来 | 只在你找她时醒来 | 说结果，不说机制 |
| 耳朵在手机上的 Quetzal App 里（Android 的前台服务常驻麦克风）……识别用「语音」页里的 Azure 密钥。 | （删除） | 合并页面后不言自明 |
| 1 只认清晰的近距离说话，3 轻声也算。太灵敏会把电视…… | 只听近处 / 适中 / 轻声也听 | 选项本身就是说明 |
| 她可以同时住在多具身体里……每次醒来前拉取，醒来后推送。 | （删除） | 进阶页面的读者不需要科普 |
| 默认用官方同步服务，不用改。想自己部署…… | 地址（留空用官方） | 一个占位符说完 |
| 升级：在这台机器上再跑一次安装命令（curl ……） | （删除，关于页一键更新） | 不让用户敲命令 |
| 基座处于安全模式（反复崩溃后）：只能查看与管理，不会醒来。 | 神谷薰反复出错，暂停了醒来 | 主语是 ta，不是「基座」 |
| 申请配对码 / 完成配对 / 没收到？重新发送 | 获取配对码 / 配对 / 重新发送 | 动词即可 |
| 点火 | 启动 | 不用内部术语 |

## 4. 已经做掉的「还可以更少」

| 原来 | 现在 |
|---|---|
| 设备登录与「控制台登录」两次批准 | 一次：同步服务批准运行基座时顺带发控制台登录（旧的同步服务不给时才退回单独登录） |
| 模型页是一整套管理后台 | 默认只有「点供应商 + 粘贴 Key + 接上」，运行基座自动挑最新的能调工具的模型、试通、留两个；完整管理收进「编辑」 |
| Azure 语音要填密钥和区域 | 只填密钥，运行基座向各区域官方令牌接口探测出区域 |
| 电脑上没有向导，模型与登录要自己找 | 第一次连上、还没有模型时打开一次向导（登录、模型两步） |
| 官网账户页的子页面名与 App 不一致 | 两边都是 概览 · 添加设备 · 已登录 · 设置 |

不做的：安装时提前申请登录码——申请只要不到一秒，提前申请反而可能在用户走到这一步前过期。
