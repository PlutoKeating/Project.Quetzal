# 独立内核引擎开发路线图

本路线图基于源码基线 `f4f93c4` 和 [现状记录](README.md)，用于安排后续开发，不是功能完成清单。任务状态仅说明工作安排；实现、验证及交付事实必须在对应变更中记录。论文调研没有复现实验结果，以下适配方案属于待验证的工程建议。

## 1. 目标与本轮范围

目标是在仓库根目录建立独立 `engine/`，提供可复用的 Agent 执行内核。`runtime/` 继续作为 Quetzal 宿主，交互端通过宿主 API 使用同一 Agent。MCP 是工具来源之一，论文方法通过独立研究运行器评测后，再决定是否接入默认策略。

按小切片推进，每阶段保持可审查、可回滚的兼容入口。第一切片已抽取执行循环和通用协议类型；后续继续完成纯上下文 / 检索策略、受限研究运行器、stdio MCP 与本机 TUI，验证见 [后续切片](FOLLOWUP.md)。不同时迁移全部上下文、记忆、模型实现、工具、子 Agent 管理或客户端，不在此次抽取中改变默认执行预算。

| 工作包 | 当前安排 | 负责人 | 实施门槛 |
|---|---|---|---|
| 第一阶段：engine 协议、循环、runtime 接回及验证 | 实现及本地验证完成；全量网络测试限制见 [验证记录](EXTRACTION.md) | OpenRLHF 方向子代理实施，主代理整合 | 按本轮边界保持原行为 |

## 2. 模块边界

| 层 | 应承担的职责 | 接入方式与边界 |
|---|---|---|
| 根级 `engine/` | 消息与工具协议、模型与工具循环；后续上下文选择、记忆检索策略、经验选择、轨迹事件 | 接收显式依赖，不反向导入 runtime，不自行加载部署配置或凭据 |
| `runtime/` 宿主 | 人格与身份、身体、heart、灵魂文件及 Git 同步、mesh、权限审批、急停、脱敏、模型凭据、真实工具执行、持久化、网关及通道 | 将数据、模型调用和工具执行能力提供给 engine；维持既有对外协议 |
| 交互前端 | 发消息、会话选择、查看流式进展、取消及管理 | Flutter、未来 TUI 等经宿主 API 使用同一运行入口，不额外启动 Agent 或直接读灵魂／模型 Key |
| MCP 工具来源 | 工具发现、调用、连接生命周期与协议错误处理 | 转成统一工具描述与结果；真实执行继续经过宿主权限、脱敏与审计 |
| 离线研究运行器 | 受限任务环境、多轨迹采样、独立评分、经验提炼／优化、冻结策略对照、训练数据导出 | 使用隔离的状态、预算和工具；默认合成任务，不加载生产身体与真实灵魂 |

“记忆策略属于 engine”不意味着第一阶段把灵魂目录读写、SQLite 数据库和 Git 同步整体迁走。先分离选择算法与数据来源，原有 Markdown／FTS5 可以继续由宿主提供。

## 3. 按依赖顺序推进

阶段编号用于分类，不代表必须先完成论文实验再接 MCP / TUI。第一阶段本地验证后，工具来源与 TUI 可分别进入下一小切片；上下文接口与研究运行器按各自依赖推进，论文实验最后依据共同评测契约启动。

### 阶段一：协议与执行循环

**依赖：** 当前源码、[执行行为](EXECUTION.md)、[接口现状](INTERFACES.md)及既有测试。

1. 固定文字结束、工具调用、失败／拒绝、重复失败、空输出重试、插话、中断、停止、`finish` 和换身体的现有语义。
2. 建立独立 engine 包与通用消息／工具类型。runtime 原路径可重新导出通用类型，保留调用者兼容性。
3. 抽取 `brain.loop()`，通过小接口注入模型、工具、运行状态、事件、工具记录、急停、脱敏及日志。`finish` 与本次运行参数显式传入。
4. 普通对话、醒来及子 Agent 使用同一循环；`converse()`、`wake()` 和子 Agent 宿主编排暂留原处。`Session` 暂由 runtime 适配，不要求整体迁移。

**验收：**

- engine 独立类型检查和测试通过，不导入 `runtime/src`；导入时不创建数据库、定时器、网络连接或部署目录。
- 合成模型／工具覆盖核心执行语义；失败和拒绝保持不同状态，工具记录及返回模型的结果保持脱敏，取消后不再发起模型调用。
- 工具调用与结果保持合法配对，最终回复取原约定位置；空输出重试、插话与停止可观测。
- runtime 类型检查、相关测试及构建通过，原发布产物路径不变；依赖与构建配置准确反映新增包。
- gateway、mesh、飞书等入口无需本轮改变协议。验证范围区分本地模拟与实际模型、设备、跨身体验证。

**风险与回滚：** 迁移容易改变事件顺序、异常类型身份、停止语义与灵魂触碰同步。保留宿主兼容入口并使用一个有明确范围的提交；不要同时改默认预算、检索或执行策略。

### 阶段二：上下文与记忆策略接口

**依赖：** 阶段一验收，运行协议稳定。

宿主提供人格、身体状态、历史和记忆文档，engine 负责选择与排列。先保持现有字符预算结果，再另行设计全局 token 预算、本轮压缩与较小窗口模型故障转移。将纯分词／评分函数与文件、数据库访问分开，保留 Markdown 和 FTS5 基线。

**验收：** 同输入的选择可复现；摘要与任务约束不因窗口选择意外丢失；工具调用与结果配对不被裁剪破坏；记录检索候选、入选原因和预算成本；模型窗口变化有明确处理，不把字符数宣称为 token 数。

**负责人：** 主代理指派上下文／记忆实现者；PRIME 方向负责经验检索需求与评测建议。可分别推进纯上下文选择与纯检索算法，但共享类型先定稿。

### 阶段三：执行轨迹与受限研究运行器

**依赖：** 阶段一运行事件；阶段二并非所有基础轨迹工作的前置条件，经验检索实验则需要其策略接口。

engine 输出运行、步骤、模型调用、工具结果、终止原因和用量事件；宿主负责持久化及脱敏。离线运行器使用自己的模型／工具／状态存储，设置步骤与用量上限，不默认执行真实外部动作。结果评估区分成功、失败、取消、超限、未知，不以模型自述完成作为唯一评分。

**验收：**

- 可关联任务、轨迹、经验来源和评分；记录数据集、模型、工具环境、策略与经验库版本。
- 相同任务能比较冻结策略；原始私有数据与运行产物在仓库外，公开样例使用合成或脱敏资料。
- 不影响生产用量、真实会话或灵魂文件；模拟工具拒绝／失败与取消语义一致。
- 工具记录只有执行身体本机拥有的现有边界被保留，不能假定所有身体具有完整轨迹。

**负责人：** 主代理分配基础设施实现；三个论文方向共同定义所需轨迹字段和评价接口。运行器独立后，各论文实验可以并行。

### 阶段四：论文实验工作包

#### PRIME：结构化经验与条件检索

**负责人：** PRIME 方向子代理；**依赖：** 阶段二策略接口、阶段三任务和证据基线。

- P1：定义经验候选：情境、行动、观测结果、教训、适用条件、来源引用、阶段和证据状态。先通过既有笔记格式存储小规模实验，不立即改变灵魂规范。
- P2：比较现有 FTS5、条件过滤、轻量重排；允许零条命中，为经验设置独立上下文预算。
- P3：比较冻结经验库与候选改写；顺序为去重／失效标记、证据驱动改写、泛化，最后研究交叉组合。低频经验先归档，不直接删除。
- P4：验证同一经验库在不同执行模型、工具版本及任务环境中的适用性。

**验收：** 经验忠实度、无来源断言率、重复率、检索适用性、误用率、任务完成率、成本及延迟均有基线。用户偏好区分明确表达、推断和未知，不得因情绪推断任意覆盖 `USER.md`；人格、个人事实与策略经验不采用同一剪枝规则。

**迁移边界：** 持续会话没有论文固定交互终点，不照搬按 25%／75% 轮次划阶段；没有真实奖励时不套用成功／失败阈值或虚构回报归因。官方源码尚未确认，实验实现须明确属于本项目适配而非官方复现。

#### Training-Free GRPO：同任务多轨迹比较与经验优化

**负责人：** Training-Free GRPO 方向子代理；**依赖：** 阶段三有界任务、可验证结果及经验版本；复用阶段二上下文接口。

- G1：在相同任务条件下生成多条候选轨迹，固定工具与评价环境，记录采样成本。
- G2：使用可核查结果比较候选，研究组内差异如何提炼为经验，不只保留模型自评。
- G3：比较原经验、优化经验及无经验基线，隔离经验构建集与测试集。

**验收：** 评分可靠性、轨迹多样性、经验泛化、完成率及包含所有采样成本的费用／延迟报告齐备；组内分数相同或评分未知时有明确处理。多次采样限定研究环境，不对真实用户外部动作反复试错，不默认增加每次线上对话调用数。

#### OpenRLHF：离线训练与数据契约

**负责人：** OpenRLHF 方向子代理；**依赖：** 阶段三轨迹／评分契约，以及另行确认的数据和计算资源。

- O1：审计本地上游版本、训练接口和论文版本差异，确定受限实验依赖。
- O2：从研究运行器导出经过验证的轨迹与奖励／偏好数据，记录来源、划分与模型版本。
- O3：在仓库外运行最小训练实验，对照原模型和非训练策略；评估权重加载及服务接口兼容性。

**验收：** 导出数据有可追溯证据，训练／评测划分独立；报告资源、失败与成本；模型工具协议、上下文长度及宿主路由兼容性通过。GPU、权重和 checkpoint 不成为 engine 的运行时必要依赖，未训练或未评测的模型不得报告为改进成果。

三个方向复用同一任务与结果契约，但分别维护策略版本、预算和对照。论文报告的收益不等同 Quetzal 部署收益；未验证方法不默认上线。候选策略至少比较完成率、失败率、成本与延迟，并检查模型、工具、用户偏好和环境漂移。

### 阶段五：MCP 工具来源

**负责人：** Training-Free GRPO 方向负责设计，主代理安排实现；**依赖：** 阶段一工具接口、宿主权限映射及生命周期设计。

统一来源命名空间、描述、参数、调用结果、权限类别、取消及协议错误。MCP 连接、凭据与审批仍由宿主管理，工具输出作为资料处理，不能因来源协议而升级为系统指令。

**验收：** 名称冲突、断连、工具列表变化、取消、异常结果均可测试；调用经过权限、脱敏与审计；密钥与完整保密参数不进入前端事件。MCP 可在研究实验外独立推进，无需等待论文算法结论。

### 阶段六：交互前端第一切片

**负责人：** Training-Free GRPO 方向负责接口设计，主代理另行安排实现；**依赖：** 既有宿主 gateway 协议及第一阶段兼容性验证。

未来 TUI 第一切片可经既有 gateway RPC 支持会话选择／新建、消息输入、流式进展、工具状态、取消和退出。不得导入 engine 或启动第二个 Agent；先处理本机认证，远程连接须保留既有 TLS 配对与信任边界。保密输入不能作为普通消息或终端回显；不支持时应明确拒绝并引导控制台。

**验收：** 使用本地模拟 gateway 覆盖认证、断连、会话、取消和 Windows 入口行为；终端不输出令牌、保密值或完整工具参数；Ctrl+C、退出与连接失败有清晰语义。本机 TUI 第一切片已实施；远程配对与保密值终端输入仍未实现。

## 4. 抽取时必须审视的耦合

| 当前位置 | 隐含依赖 | 处理顺序 |
|---|---|---|
| `mind/brain.ts` | 全局会话队列与 running／waiting Map、heart busy 所有权、placement／对话／停止路由回调 | 本轮只抽循环，保留宿主编排；后续状态归属显式实例 |
| `mind/activity.ts` | 全局 live Map、config／bus、Session 心跳与超时定时器 | 先适配现有 Session，后续明确实例隔离及 close 生命周期 |
| `mind/agents.ts` | 子 Agent／Session Map、kv、身份与 heart nudge | 先复用循环，后台任务管理另行拆分 |
| `memory/memory.ts`、`retrieval.ts`、`index.ts` | memory 与 retrieval、retrieval 与 index 双向导入；全局写锁、index ready 缓存、store.db | 先分离纯分词／评分，宿主保留文件／数据库与写锁 |
| `mind/prompt.ts` | 人格、body、heart、soul、听觉、提醒、保密库及其他会话直接读取 | 作为宿主上下文装配，后续提供显式提示块 |
| `providers/router.ts` | 凭据注册表、全局 Key 游标、addUsage、目录与兼容层 | 模型调用接口隔离，凭据与用量实现留宿主 |
| `mind/tools.ts` | 审批、脱敏、审计、body 路由与 finally 中 soul.touched | 本轮整条执行链留宿主，避免漏同步或泄露 |
| tools／brain／hearing | 动态导入 brain、hearing 导入 converse、brain 导入 hearing | 保留兼容入口，后续按职责消除循环 |

异常类型在拆包后必须保持单一来源，否则 `instanceof` 中断判断可能失效。类型重新导出、Node TypeScript 直跑、CJS 打包和平台发布脚本要一起核对。首阶段不以复制一套循环长期并存代替抽取，也不为拆包引入大型插件容器。

## 5. 并行、交付与证据

- 协议确定后，engine 循环、runtime 适配与构建检查可分工；同一文件由一个负责人修改。
- 上下文纯策略与研究运行器可在稳定执行接口后并行；论文实验在共同任务契约确认后分别进行。
- 主代理负责汇总变更、检查工作区、匹配文档与配置、本地提交；子代理本轮不自行提交。
- 每阶段记录修改文件、命令、结果和未运行验证。测试通过、实际模型验证、真机／跨身体验证及发布是不同证据，不互相替代。
- 进入下一阶段前检查是否仍满足小切片边界；需要改变现有产品行为时先给具体设计和验收，不把算法实验隐含在目录迁移中。
