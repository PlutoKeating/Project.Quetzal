# 上下文组装、预算与压缩

本页依据 [prompt.ts](../../runtime/src/mind/prompt.ts)、[brain.ts](../../runtime/src/mind/brain.ts)、[retrieval.ts](../../runtime/src/memory/retrieval.ts) 和 [attachments.ts](../../runtime/src/mind/attachments.ts)。初始基线见 [BASELINE.md](BASELINE.md)；循环已提取至 [engine/src/loop.ts](../../engine/src/loop.ts)，本页的上下文策略仍由 runtime 组装，首次提取没有改变预算和压缩行为。

## 1. 请求由哪些部分组成

对话在一轮开始时先拉取灵魂，然后建立：`systemPrompt(当前输入, {conv})` → `history(conv, 当前消息id)` → `userMessage(当前输入与附件)`。工具循环随后追加 assistant 工具调用、tool 结果、插话 / 提醒与图片。

思考 / 做梦从 `systemPrompt(原因 + 意图)` 与任务提示开始，没有自动载入某个当前会话的完整历史，但系统提示包含近期会话摘要和日记。子 agent 使用自己的 `agentPrompt()` 和显式任务 / context，详见 [执行文档](EXECUTION.md)。

系统提示是一次组装的快照；内省和正式醒来分别调用组装函数，但每个工具循环内部不重新生成。写入记忆、身份变化、远端记忆到达等，不会重建当前 system 消息。工具定义也在 `loop()` 入口取得快照，当前轮次中新建工具不自动进入这份定义；`callTool()` 查找实现时则重新调用 `allTools()`。

## 2. systemPrompt 顺序

| 顺序 | 段落与事实来源 |
|---|---|
| 1 | `SOUL.md` 人格；缺失时种子人格，显示名来自 `agent.json` |
| 2 | 处境：身份、多身体语义、时间与日历、提醒、并发认领和行动记录约定 |
| 3 | 红线：灵魂 / 公开代码边界、同步、密钥、网关、外部操作与不可信资料 |
| 4–5 | `MEMORY`、`USER` 条目预算视图 |
| 6 | 笔记目录树与摘要，指向 `note_read` / `note_list` / `recall` |
| 7 | 非空话题时自动检索相关笔记 / 日记 |
| 8–9 | `thought` 想分享的一句话；保密库名字、说明、路径，不包含保密值 |
| 10–12 | 当前会话沙箱 / 真实环境、身体描述、在线其他身体及工具 |
| 13–15 | 技能与本机自造工具情况、会话与子 agent 使用说明、开启时的听觉说明 |
| 16–18 | 内驱力 / 生物钟 / 未完成念头、灵魂同步知觉、最近日记 |
| 19 | 其他会话近况：认领、进行中轮次、近期对话；醒来时包含会话 id |

技能段是可用 / 缺依赖 / 无本机实现的列表与简短描述，不是自动注入所有 `SKILL.md` 正文；需要正文时使用 `tool_read`。

## 3. 局部预算的实际含义

全部长度按 JavaScript `string.length`，即 UTF-16 代码单元计数，不是 token 计数，也不严格等于用户感知的字数。

| 内容 | 当前预算 / 范围 | 选择方式与额外内容 |
|---|---|---|
| MEMORY | 4000 | `coreView()` 选完整条目；标题、容量与未展开说明另加 |
| USER | 2000 | 同上；没有统一摊分给另一类记忆 |
| 笔记目录 | 约 2500 | 按层级与新近程度展开；截断后的提示可额外增加长度 |
| 自动检索 | 3000，最多 12 候选 | 计入来源标签和摘录；候选放不下就跳过；连接用的空行另加 |
| 最近日记 | 6 个文件，正文合计 3000，每文件最多 1500 | 取文件尾部；来源标题另加 |
| 其他会话 | 约 4000 | 认领先列，接 live 轮次；查询最近 8 会话，排除当前后最多展示 5 个，每会话最多 4 条、每条约 160 字符 |
| 当前历史 | 最近 80 条，16000 | 从新向旧累计，超预算即停止；最后按时间顺序呈现 |
| 历史详细过程 | 最近 3 条 agent 回复 | 每条 `describeProcess()` 默认 1200；更早只给工具计数；包含在历史预算中 |
| 当前文本附件 | 内容合计 60000 | 整个文件放得下才内联，否则只给路径；标签与代码块另加 |
| 单次工具结果 | 原文前 12000 | 失败前缀和重复失败提醒另加，之后每次调用继续累积 |
| 模型输出 | 默认 `brain.maxOutputTokens=4096` | 输出 token 上限；不约束输入或整轮消费 |

人格、系统提示的其他部分、当前输入、工具 JSON Schema、图片等没有纳入同一个全局预算。供应商模型的 `context` 只是配置元数据，路由故障转移到较小窗口模型时也不据此重新裁剪。没有 tokenizer、窗口余量计算、自动摘要触发或上下文过长的专门压缩重试。

常驻条目预算不足时先按话题相关性排序，再从文件末尾往前补足，最终按原文件顺序呈现；单个过长条目会被跳过，不切片。这里的“新近”是条目位置，不是逐条写入时间戳。

## 4. 历史重建

`history()` 从最近 80 条里找最新 `ambient / 摘要`，只使用摘要及之后的记录，再从最新向前按预算选取。消息按时间而非跨身体 id 大小排序；当前输入和排队的后续输入不当成已完成历史使用。

数据库角色 `agent` 映射为模型 `assistant`；用户、环境、摘要、交接、子 agent 报告映射为模型 `user`。agent 回复前单独插入一条“基座附注”，写入时间、执行身体与过程摘要，assistant 内容仍是原回复。

原始工具调用消息不从数据库完整恢复进历史：回放的是过程描述和回复，完整参数 / 输出另由 `tool.detail` 查本机记录；`recent_actions` 查询审计。历史附件只有名称与路径，图片不会每轮重发。

摘要若已不在最近 80 条内，就不再被这次查询取到；摘要本身过长，也可能在历史预算选择时被排除。当前没有独立于消息窗口的“固定会话摘要”存储槽。

## 5. 压缩与新会话

`session_compact` 仅在对话中调用，将摘要写入原会话的 `ambient / 摘要`。模型自己提供摘要时直接保存；未提供时 `summarizeConv()` 用 quick 模型代写：输入来自 `history(..., 24000)`，仍只查询最近 80 条，过滤基座附注，要求不超过 800 字，输出预算 1200 tokens。800 字是提示要求，不是结果强制截断。

压缩下一轮 `history()` 才生效。当前循环的数组保持原样，调用压缩之后也不会降低本轮输入长度；当前未落盘的完整工具过程不能被 quick 摘要自动读取。更早原文仍留在 SQLite，能通过控制台或 recall 找回。

`session_new` 新建会话，可写 `ambient / 交接`，设置 `switchTo` 并推送切换事件；当前轮次的最终回复存到新会话。它同样不清空当前模型上下文，后续轮次才从新历史开始。

## 6. 多模态与插话

当前附件图片通过 `loadImage()` 处理，大图片缩至长边 1600 的策略见 [images.ts](../../runtime/src/mind/images.ts)；每轮 `Session.seen` 记已附带 / 已查看的路径。`view_image` 新图放入 `Session.images`，下一次模型调用前作为 user 图片消息加入。同路径再次调用只给说明，不再发送。

路由发现图片后只选择有看图能力的模型：手动 `vision` 优先，否则查模型目录；未知按不支持处理。没有可看图模型时去掉图片、保留文字说明和本地路径。这里没有统一图片 token 成本估算。

`drain()` 在模型调用前消费 inbox。插话、打断、子 agent 报告与灵魂提醒都可能继续增长当前消息数组；打断保留已经输出的部分。循环不会因多次插话自动重算检索话题或重新组装 system 提示。
