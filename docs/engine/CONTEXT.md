# 当前上下文管理

生产对话、醒来任务和子 Agent 经同一 `engine.runTurn()` 执行。宿主在每一步通过 `prepareContext` 附上 `prepareForModel`；路由选定实际模型后，按该模型窗口重建本次输入视图。实现见 [动态上下文](DYNAMIC_CONTEXT.md)、[context-manager.ts](../../engine/src/context-manager.ts)、[context.ts](../../runtime/src/mind/context.ts) 与 [router.ts](../../runtime/src/providers/router.ts)。早期字符预算方案属于 [初始基线](BASELINE.md) 和 [策略提取快照](CONTEXT_EXTRACTION.md)，已不代表默认生产行为。

## 输入与预算

人格、身份、身体状态、权限与技能仍由宿主构造系统提示。生产 `dynamic: true` 路径不再将 MEMORY、USER、整个笔记目录、自动 recallBlock 与最近日记固定常驻。每一步根据目标、最近用户输入、阶段、标签和当前工具重新选择结构化记忆与兼容旧记忆，再按模型总预算组装。

输入、工具 Schema、图片估计、输出与安全余量统一计入计划。文本采用 UTF-8 字节数作保守估计，图片采用启发式成本；这不是精确 tokenizer，也不能保证未知供应商的真实计费 token。窗口优先使用模型元数据，未知时才用 `brain.contextWindow`；输出同时受请求、模型上限和窗口四分之一限制。切换到小窗口模型会重新准备，固定内容放不下时抛 `ContextOverflow` 并换下一个模型，不发送超限视图。

系统消息、任务工作状态、当前用户输入、最近消息组和未完成的工具调用受保护。工具调用与结果成组保留。原始 `Msg[]` 不被截断；超长工具正文只有在存在可回查引用时才生成节选。旧消息按有界批次生成 quick 摘要，缓存摘要；摘要失败只在所有原文有引用时使用带来源的退路，否则明确拒绝。摘要是历史资料，不能产生新授权。

## 工作状态与全文回查

`task_state` 更新目标、约束、未决问题、阶段及标签；工具证据由宿主从执行结果提取，模型不能自行提交已验证证据。会话工作状态与最后上下文计划保存在本机 kv，摘要槽可跨轮次延续；它们不进入灵魂 Git。

`context_read` 只允许当前活动轮次读取同会话已建立的引用，支持分页。SQLite `context_sources` 最多保留 5000 项，每项最多 256 KiB；大于单项上限且没有已有消息／工具指针的正文不能假称可完整恢复。历史消息通过原始消息 id 回查，工具通过 call 与 turn 联合查找，已完成回复另存详细工具引用。图片二进制不进入此缓存，过期或非本机来源可能无法恢复。

`history()` 默认读取最近 1000 条并交给总预算管理，而不是先按 16000 字符裁掉。历史展示中的过程仍可节选，但原始 SQLite 消息与本轮完整工具记录保留。超出这段读取窗口的对话仍可显式 recall，不能宣称无限历史已经自动进入上下文。

## 兼容入口与边界

`session_compact`、`session_new`、`memory`、`note_*` 和显式 `recall` 保留。手工会话摘要继续影响后续历史；当前自动压缩独立于这些工具，能在本轮下一次模型请求生效。工具定义仍是轮次入口快照；新建工具不会自动改变本轮 Schema。

模型不响应取消时，摘要和语义选择也会通过宿主超时／取消竞争结束等待；急停阻止后续准备。语义选择有独立日预算、短缓存与词面回退；配置和限制见 [记忆替代交付记录](MEMORY_REPLACEMENT.md)。宿主仍是进程级服务，并未实现多个互不共享数据库与全局状态的 runtime 实例。
