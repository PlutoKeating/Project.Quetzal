# 受限离线研究运行器

[engine/src/research.ts](../../engine/src/research.ts) 提供 `runResearchGroup()`，真实调用现有 `runTurn()` 执行同一任务的多个独立样本。它是三论文方向共用的实验基础，不包含 PRIME 蒸馏／演化、Training-Free GRPO 经验优化或 OpenRLHF 训练，也不改变生产 runtime。

## 运行合成示例

仓库根目录执行：

```bash
npm run research:demo --prefix engine
```

[示例](../../engine/examples/research.ts) 使用合成模型和加法工具执行三个样本；两个答案正确，一个答案故意错误，由独立评分函数比对工具观测与最终答案。正常输出为 2 个 success、1 个 failure、6 次模型调用、3 次工具调用、18 个报告 tokens。这些数字只描述合成示例，不是模型性能或论文复现结果。示例不读取 Key、部署配置、生产数据库或私有灵魂，不默认调用外部工具。

## 接口与独立环境

输入包括任务标识、样本数、显式限制、可选 `AbortSignal` 和 `factory({task, sample, signal})`。每个样本都会调用 factory；factory 必须创建新的环境对象、模型／工具状态和评价状态。复用同一环境对象会报错；不同对象背后共享闭包、数据库或远端状态无法由运行器自动发现，调用方必须保证隔离。

环境提供初始消息、工具描述、模型调用、可选工具执行、独立评分和 cleanup。运行器复制消息与工具快照，避免循环改动环境的初始输入；只有该环境声明的工具能进入其执行端口，未提供执行器或未声明工具返回 denied。特殊 `finish` 保留现有循环语义；任务成功仍由评分决定。

模型请求、响应、进展事件、完整工具记录构成结构化轨迹。工具记录参数默认替换为 `{}`，环境可显式提供 `redactArgs`；这只处理工具记录参数。`trace.models` 中的原始消息／响应、`tools.result`、error 和 assessment.evidence 仍可能含私有资料，真实环境的返回值不等于已脱敏可公开数据。接入真实数据前应由独立适配器完成脱敏，并在仓库外保存运行产物。不得以此入口连接生产身体或对真实外部动作反复采样。

## 限制与停止语义

| 限制 | 执行位置与语义 |
|---|---|
| `maxSteps` | 每次循环 step 事件前；空输出重试也占步骤 |
| `maxModelCalls` | 每次发起模型请求前，记录实际发起次数 |
| `maxToolCalls` | 每次普通工具执行前，包含 denied；可设为 0 |
| `maxReportedTokens` | 使用模型报告的 input + output；调用前已达阈值则不再调用，单次返回后超限则停止后续处理 |
| `maxOutputTokens` | 传入模型请求的输出上限，端口必须自己遵守 |
| `timeoutMs` | 覆盖单样本创建环境、执行和评分的总等待时长；清理另有同长度的等待上限 |
| 调用方 `AbortSignal` | 终止当前样本等待；不再创建后续样本。启动前已取消时返回空样本组 |

限制在组入口复制，不能通过随后改动输入配置提高门槛。样本按顺序执行，每次模型调用前让出事件循环，让立即返回的模型也不会通过微任务队列饿死超时计时器。

factory、chat、execute 和 evaluate 都采用可取消等待。即使它们忽略信号或永不完成 Promise，运行器仍会返回 timeout／cancelled；不会把晚到的模型结果追加到已返回轨迹。这个机制无法抢占阻塞 JavaScript 线程的同步函数，也不能强制终止已经发出的外部请求或副作用。需要强制隔离的实验应另用进程级沙箱；本切片默认只演示合成端口。

## 清理与评价

每个成功创建且归本样本所有的环境都会调用 cleanup，一次样本不会重复调用。超时后才创建完成的环境到达时仍调用 cleanup。factory 永远不返回环境时没有对象可清理；忽略信号的端口必须自行管理其后台资源。cleanup 本身卡住时停止等待并记录清理失败；它的底层工作未必已经结束。单样本最坏等待包含执行与清理两个时限，样本组不是单一全局 timeout。

独立评分返回 `{status, score, evidence}`：status 为 success／failure／unknown，score 为有限数或 null，evidence 为字符串数组。模型结束、返回 finish、声称完成或工具返回 ok 均不自动成为 success。评分非法、失败、超时，或执行被限制终止时记录 unknown，并保留终止原因。即使评价成功，cleanup 失败也会单独记录在样本 error 中，不能由任务成功推断资源已释放。

组输出保留任务、限制、各样本及累计步骤、模型调用、工具调用、报告 tokens、success／failure／unknown 数量。可选只读 metadata 包含 `datasetVersion`、`modelVersion`、`toolVersion`、`strategyVersion`、`experienceVersion` 和 `seed`；入口复制并冻结后放入组输出，调用方随后修改原对象不会改变记录。字段未填表示未记录，不能推断版本或复现条件；正式实验应填写全部相关版本，模型动态别名不足以证明后端权重固定。`incompleteUsage` 表示存在已发起但未取得合法响应用量的样本数；这些样本可能已经产生实际费用。

**报告 tokens 是事后统计，不是精确账单或硬费用上限。** 一次调用可以超出阈值，取消的请求可能仍被收费，未返回的用量无法计算；环境创建、评价或清理内部额外模型调用不自动计入。接入实际模型后应另外记录价格版本和所有评价／采样成本，不用缺失报告推断零费用。

## 验证与后续

[research.test.ts](../../engine/test/research.test.ts) 检查样本隔离、独立评分、组汇总、步骤／模型／工具／用量限制、忽略信号的端口、外部取消、迟到环境清理、清理超时及默认工具拒绝。

后续各论文实验需要自行固定数据集、采样参数、模型、工具环境、经验库和评价版本，并分开经验构建集与测试集。本运行器暂不提供经验优化、训练数据格式、持久化、自动重试或生产策略切换。
