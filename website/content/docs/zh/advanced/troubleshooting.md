## 安装阶段

| 现象 | 原因与处理 |
|---|---|
| 「这台手机上已经有一个运行基座在运行」 | 多半是以前装在 Termux 里的旧版还在跑，占着同一个端口。按 [从 Termux 版换过来](/docs/start/install#从-termux-版换过来) 迁移：确认灵魂已推送，卸载 Termux 版（或在 Termux 里 `sv down quetzal`），再回来安装 |
| 「运行基座 180 秒内没有响应」 | 内置运行基座没能启动。日志在 App 数据目录的 `files/home/quetzal/data/runtime.log`（需要电脑上 `adb shell run-as xyz.quetzal.console` 才能读，调试版 App 才可以），可以带着日志到 GitHub 提 issue；先试一次 **重试** |
| 「读不到网关令牌」「核对网关失败」 | 运行基座起来了但令牌对不上，多半是数据目录被手动改过。在 **控制 → 服务** 重启后再试 |

## ta 一直不醒

按顺序检查：

- [ ] **控制 → 模型**：至少一个供应商、一把 Key、一个已启用的模型，且测试连通成功。没有模型时醒来率为 0。
- [ ] **控制 → 自主性**：没有暂停自主；活跃度不是 0。
- [ ] 顶栏没有急停。
- [ ] **控制 → 预算**：今日预算没有用尽；电量高于最低电量且在充电；温度正常。
- [ ] 刚装好的前一两个小时，驱动力还在积累，安静是正常的。可以**戳一下**。

## 离线 / 被系统杀掉

- 「此刻」页出现离线横幅时，点**点火**：App 重新启动自己的前台服务（通知栏里那条「ta 住在这台手机里」）。
- 反复被杀：确认 Quetzal 在**电池优化忽略名单**里，并在厂商的自启动 / 后台管理里**放行**。个别厂商系统有独立的"省电精灵"类组件会无视白名单，需要在系统设置里关闭或禁用它（[Project.Honor9](https://github.com/PlutoKeating/Project.Honor9) 记录了一台旧手机上的做法）。
- **重启后、App 升级后离线**：有锁屏密码的手机要先解锁一次；厂商系统没放行「自启动」时，开机与升级的广播会被拦下，打开一次 App 即可，放行后就不会再这样。

## 安全模式

ta 主动告诉你"进入了安全模式"：10 分钟内启动超过 5 次。此时只开网关与飞书，不醒来、不调用模型。原因通常是配置损坏或模型层异常。看日志（手机：App 数据目录的 `files/home/quetzal/data/runtime.log`；Linux：`quetzal logs`），修复后在 **控制 → 服务** 重启。

## 模型相关

| 现象 | 处理 |
|---|---|
| 测试连通失败 | 检查 API 地址是否含版本路径（如 `/v1`）、协议是否选对、Key 是否有效 |
| 回复中途失败并换了模型 | 正常：流式 90 秒无数据块即判定失败并故障转移 |
| 图片被去掉了 | 没有能看图的模型。给某个模型手动打上 `vision` 标记，或启用目录里支持图片输入的模型 |
| 保存被拒绝「配置已过期」 | 其他地方先改过。重新加载后再改 |

## 飞书

- 显示未连接：检查 **控制 → 飞书** 的错误信息；一键创建的应用需要在飞书中**确认**才会下发凭据。
- 收不到「此刻」卡片：打开与机器人（以 agent 显示名命名）的**单聊**，发一句话。
- 卡片按钮无反应：机器人需要开启长连接事件订阅；一键接入已自动完成，手动接入请检查应用后台的事件订阅方式。

## 灵魂同步

| 现象 | 处理 |
|---|---|
| 接入失败「地址必须是 SSH」 | 用 `git@github.com:你/仓库.git`，不能用 https |
| 推送被拒 | Deploy key 没勾 **Allow write access**；或公钥没加到**这个**仓库 |
| 「身份不同，拒绝合并」 | 仓库里住着另一个 agent。给这个 agent 新建一个仓库 |
| 两边记忆看起来不一致 | 同步是事件驱动的：等 ta 下一次醒来 / 对话，或在 **灵魂同步** 页点立即同步 |

## 网页控制台（Linux）

- 打开 `http://127.0.0.1:7788/` 要配对码：网关只对**同一台机器**的浏览器免配对码；用局域网 IP 或主机名访问就不算；改用 `127.0.0.1` 或 `localhost`。从别的机器访问，请 `ssh -L 7788:127.0.0.1:7788 <那台机器>` 转发后在本机浏览器打开，或（开了 `--lan` 时）打开 `https://<那台机器的地址>:7789/`、核对证书指纹后用配对码，或在 App 里配对。
- App 提示「运行基座已改为加密连接，请重新配对」：旧版 App 保存的是 `http://<地址>:7788`，新的运行基座在局域网上只接受 HTTPS。在配对页保存新地址（只填 IP 即可，自动用 `https://…:7789`），核对证书指纹后重新配对。
- 页面空白或中文是方块：`quetzal status` 看服务是否运行；浏览器强制刷新。网页版自带中文字体，不依赖外网。
- 装完没有自动打开浏览器：没有桌面会话（服务器、ssh 登录）时只打印地址；`quetzal open` 再试。
- 一键安装脚本中途失败：它会打印日志尾巴，完整日志在 `~/.quetzal/install.log`；修好原因后再跑一次同一条命令即可（幂等）。`apt` 被锁住多半是系统正在后台更新，等几分钟。Alpine 请先 `apk add bash curl`；NixOS 请先自备 Node.js 22.13+（nvm 的二进制跑不了）。
- 重启后 ta 没醒：`loginctl show-user $USER -p Linger` 不是 `yes` 就执行 `sudo loginctl enable-linger $USER`（没有登录会话时用户服务默认不跑）。没有 systemd 的机器看 `crontab -l` 里有没有 `@reboot …/quetzal-supervise`，没有 cron 守护进程的话开机后手动跑一次。
- 应用列表里的「Quetzal」打开的是普通浏览器标签、任务栏没有 Quetzal 图标：独立窗口需要 Chromium 系浏览器（Chrome / Chromium / Edge / Brave / Vivaldi）；只有 Firefox 时用默认浏览器打开。
